FastAPI Quick Start

Quick Start code-first ~15 min

FastAPI turns ordinary Python functions into a web API — a program other apps (and browsers) can call over the internet. You write a function, add one line above it, and FastAPI handles the web plumbing, validates the data, and even generates interactive docs. New to Python? Skim the Python Quick Start first.

⬇️ Get the runnable code

A fuller, ready-to-run project for this quick start ships with the course: the HR Skills API — routers, Pydantic v2 models, middleware and dependency injection over the same domain the rest of the course uses. It lives in fast-api/:

terminal
cd fast-api
uvicorn app.main:app --reload
# then open http://127.0.0.1:8000/docs
The domain, in one line

Employees have skills rated 1–5; requisitions require skills at a minimum level; some of those are mandatory. A candidate below a mandatory bar is blocked — no score saves them. Every endpoint below is a view onto that.

EndpointDoes
GET /employees?available_only=truethe directory, optionally just the bench
GET /requisitions/{job_id}one open role and the skills it needs
GET /requisitions/{job_id}/candidateseveryone scored and ranked, best first
POST /requisitions/{job_id}/shortlistshortlist someone — 409 if they are blocked

1. Install & run

terminal
pip install "fastapi[standard]" uvicorn

# save the code below as main.py, then run the dev server:
uvicorn main:app --reload      # main = file, app = the FastAPI object
# now open http://127.0.0.1:8000  and  http://127.0.0.1:8000/docs

--reload restarts the server automatically when you edit the file. uvicorn is the program that actually runs your app.

2. Hello, API

main.py
from fastapi import FastAPI

app = FastAPI()

@app.get("/")          # handle GET requests to "/"
def home():
    return {"message": "Hello, API!"}

Visit / and you get back JSON: {"message": "Hello, API!"}. That @app.get("/") is a decorator — it wires your function to a web address. Returning a Python dict automatically becomes JSON.

🌐 The 4 verbs you'll use

@app.get reads data · @app.post creates · @app.put updates · @app.delete removes. Same pattern for each.

3. Path & query parameters

main.py
# Path parameter: part of the URL.  /employees/E1002
@app.get("/employees/{employee_id}")
def get_employee(employee_id: str):    # type hint -> FastAPI converts & validates
    return {"employee_id": employee_id}

# Query parameters: after the ?.  /requisitions/J2001/candidates?limit=5
@app.get("/requisitions/{job_id}/candidates")
def rank_candidates(job_id: str, limit: int = 3):   # limit has a default
    return {"job_id": job_id, "limit": limit}

The type hints aren't decoration — FastAPI uses them to convert and validate input. Ask for ?limit=abc and it returns a clean 422 automatically, no code needed. You can go further and validate the range too:

main.py
from fastapi import Query

@app.get("/requisitions/{job_id}/candidates")
def rank_candidates(job_id: str, limit: int = Query(3, ge=1, le=20)):
    ...        # ?limit=0 and ?limit=999 are now both rejected, with a clear message

4. Request bodies with Pydantic

For POST/PUT, the data arrives in the request body as JSON. Describe its shape with a Pydantic BaseModel and FastAPI validates it for you:

main.py
from enum import Enum
from pydantic import BaseModel, Field

class Availability(str, Enum):
    bench = "bench"
    allocated = "allocated"

class SkillRating(BaseModel):
    skill: str = Field(min_length=1, max_length=60, examples=["Apache Spark"])
    level: int = Field(ge=1, le=5, description="1 aware · 3 works independently · 5 expert")

class EmployeeCreate(BaseModel):
    name: str = Field(min_length=1, max_length=120, examples=["Priya Raman"])
    location: str = Field(min_length=1, max_length=60)
    availability: Availability = Availability.bench     # optional, defaults to bench
    experience_years: float = Field(ge=0, le=50)
    skills: list[SkillRating] = Field(default_factory=list)

@app.post("/employees")
def create_employee(data: EmployeeCreate):   # FastAPI parses & validates the JSON body
    return {"received": data.name, "skills": len(data.skills)}

Post a skill at "level": 9 and you get an automatic 422 naming the field and the rule — no route ever has to check a level again. Validating at the edge is why the scoring code in store.py is so short: by the time data reaches it, it is already known-good. This is fast-api/app/models.py.

A str Enum earns its keep in the docs

Because Availability subclasses str, it serialises as plain JSON and shows up in /openapi.json as a fixed set — so /docs renders a dropdown instead of a free-text box, and client generators produce a real enum type.

5. Response model & status codes

main.py
class Employee(EmployeeCreate):     # adds server-set fields to EmployeeCreate
    employee_id: str
    created_at: datetime = Field(default_factory=lambda: datetime.now(timezone.utc))

@app.post("/employees", response_model=Employee, status_code=201)
def create_employee(data: EmployeeCreate):
    return store.create_employee(data)   # response_model shapes what goes back out

response_model=Employee guarantees the output shape (and hides fields you don't include). status_code=201 means "created." Employee inherits from EmployeeCreate, so it reuses the same validation — the client cannot invent an employee_id, because that field only exists on the way out.

6. Async endpoints

main.py
@app.get("/slow")
async def slow():                 # use async when you await I/O
    data = await fetch_from_db()   # e.g. a database or another API
    return data

Use async def when your function awaits something (a database, another API). It lets one server handle many requests while waiting. Plain def is fine when there's nothing to await.

8. Returning errors

main.py
from fastapi import HTTPException, status

@app.get("/employees/{employee_id}", response_model=Employee)
def get_employee(employee_id: str):
    employee = store.get_employee(employee_id)
    if employee is None:
        raise HTTPException(status.HTTP_404_NOT_FOUND, detail="employee not found")
    return employee

raise HTTPException(...) sends a proper HTTP error (like 404) with a JSON message, instead of crashing.

Pick the code that tells the client what to do next. Shortlisting a blocked candidate is not a 400 — the request was perfectly well-formed:

routers/candidates.py
match = store.score(employee, requisition)
if match.blockers:
    raise HTTPException(
        status.HTTP_409_CONFLICT,
        detail=f"{match.name} is missing mandatory {', '.join(match.blockers)}",
    )
real response
POST /requisitions/J2001/shortlist  {"employee_id": "E1005"}
409  {"detail": "Vikram Iyer is missing mandatory Python, SQL"}

422 "your JSON is wrong" · 404 "no such thing" · 409 "understood, but it conflicts with the current state". That distinction is what lets a client tell a bug apart from a business rule.

9. Dependencies (shared logic)

main.py
from fastapi import Depends

class HRStore:                       # a stand-in for an HRMS
    def list_employees(self, available_only: bool = False) -> list[Employee]: ...

_store = HRStore()
def get_store() -> HRStore:          # the dependency provider
    return _store

@app.get("/employees", response_model=list[Employee])
def list_employees(store: HRStore = Depends(get_store)):   # injected
    return store.list_employees()

Depends runs shared setup (a store, a DB connection, auth) before your endpoint and passes the result in — write it once, use it everywhere. This is fast-api/app/store.py.

Why this matters for tests

Because the store arrives through Depends, a test can swap it for a fresh one with app.dependency_overrides[get_store] = lambda: HRStore() — so no test can see another test's shortlist. A module-level global would make that impossible without monkey-patching.

10. Routers — split a growing app into files

One main.py with every route gets unwieldy fast. An APIRouter is a mini-app: you group related routes in their own file, then plug it into the main app. Same decorators, just @router instead of @app.

routers/candidates.py
from fastapi import APIRouter, Depends, status

employees_router = APIRouter(prefix="/employees", tags=["employees"])
requisitions_router = APIRouter(prefix="/requisitions", tags=["requisitions"])

@employees_router.get("", response_model=list[Employee])       # GET /employees
async def list_employees(store: HRStore = Depends(get_store)):
    return store.list_employees()

@requisitions_router.get("/{job_id}/candidates", response_model=list[MatchResult])
async def rank_candidates(job_id: str, store: HRStore = Depends(get_store)):
    requisition = store.get_requisition(job_id)
    if requisition is None:
        raise HTTPException(status.HTTP_404_NOT_FOUND, detail="requisition not found")
    return store.rank(requisition)
main.py
from fastapi import FastAPI
from app.routers import candidates

app = FastAPI(title="HR Skills API")

app.include_router(candidates.employees_router)      # plug the routers in
app.include_router(candidates.requisitions_router)

The prefix is added to every route in that router, so you don't repeat it. tags=[...] groups the endpoints under a heading in /docs — with two routers you get two tidy sections instead of one long list. This is fast-api/app/routers/candidates.py.

🧩 Handy extras on a router

Apply things to a whole group at once: APIRouter(prefix="/admin", dependencies=[Depends(verify_admin)]) protects every admin route with one line. That pairs the dependencies idea with routers.

11. Middleware (runs on every request)

Middleware is code that wraps every request: it runs just before the request reaches your endpoint, and again just after the response is built. Think of a security desk everyone passes on the way in and out — perfect for logging, timing, adding headers, or auth checks you want applied everywhere.

main.py
import time
from fastapi import FastAPI, Request

app = FastAPI(title="HR Skills API")

@app.middleware("http")
async def add_timing_header(request: Request, call_next):
    start = time.perf_counter()
    response = await call_next(request)   # run the actual endpoint
    elapsed_ms = (time.perf_counter() - start) * 1000
    response.headers["X-Process-Time-ms"] = f"{elapsed_ms:.2f}"
    return response

The one rule: call await call_next(request) to pass control to your endpoint (or the next middleware), then do something with the response before returning it. Code before that line runs on the way in; code after runs on the way out.

The one you'll almost always need: CORS

By default a browser blocks a web page from calling your API if it's on a different address. CORS middleware lets you allow specific front-ends. FastAPI ships with a ready-made one:

main.py
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],          # tighten to real origins in production
    allow_methods=["*"],
    allow_headers=["*"],
)

Two ways to add middleware: the @app.middleware("http") decorator for your own logic, or app.add_middleware(SomeMiddleware, ...) for prebuilt ones like CORS, GZip, or trusted-hosts.

🔁 Middleware vs. dependencies

Use middleware for cross-cutting concerns on all requests (logging, timing, CORS). Use dependencies when only some routes need it (like auth on protected endpoints). Order matters: middleware added later runs "outermost," wrapping the ones added before it.

Everything is a 400422 = malformed JSON · 404 = missing · 409 = valid but conflicts with state.
Validating inside routesPut the rule on the model (Field(ge=1, le=5)) and every route gets it free.
