AgentCore

Seven capabilities, taught by moving one HR recruiting system from three terminals on a laptop to five deployed runtimes behind one front door.

Runtime · Gateway · Memory · Identity · Observability · Code Interpreter · Browser

Opening: the promise of this deck is not "here is a new agent framework". It is "here is what happens to the agent you already built when other people can call it." Arrow keys to move, N for these notes, O for the slide menu.
The problem

Everything that makes an agent work on a laptop is what breaks in production

On the laptop
  • The data is a module-level Python list
  • The agents are hard-coded 127.0.0.1 ports
  • The conversation dies with the process
  • When an agent loops, the evidence is in someone else's terminal
  • Nobody asks who is allowed to run it
What it needs instead
  • A system of record other services can read
  • An address that survives a redeploy
  • Memory that outlives the container
  • One trace across every hop
  • An identity at the door and a role on every call

AgentCore answers each of those — and this deck maps them one to one.

Ask the room which of the five left-hand bullets they currently have in production. Usually it is "the ports" and "the tracing".
The distinction to hold on to

A framework decides how your agent thinks.
A platform decides what happens when other people can call it.

Strands · LangGraph · CrewAI

Prompts, tools, the reasoning loop, multi-agent patterns. Your code.

AgentCore

Hosting, tool access, memory, auth, traces. Everything around your code — and it does not care which framework you used.

Which is why this deck has almost no prompt engineering in it, and a great deal about ports, roles and session ids.

If someone asks "does this replace LangGraph?" — no. You can put a LangGraph agent in Runtime and change nothing about how it thinks.

Part one

One HR recruiting desk

Twelve employees. Six open requisitions. One function that decides who fits.

Every capability that follows is judged on one question: does it protect the word blocked?
The example

Skills rated 1–5, requirements with a minimum level — and some of them mandatory

AgentCore changes where match() runs. It does not change who has to defend the number.

The alias table is why find_by_skill("pyspark", 4) finds people whose record says "Apache Spark" — not the model, not fuzzy matching.
J2001 · Senior Data Engineer, Bengaluru
E1002 Priya Raman     100% strong    blockers=[]
E1003 Rahul Menon      61% blocked   blockers=['Apache Spark']
E1005 Vikram Iyer      50% blocked   blockers=['Python', 'SQL']

The ranking is by score.
The decision is the verdict.

Rahul is second by score and cannot be hired. Distribution adds a failure mode a laptop does not have: every hop is a chance to paraphrase, and paraphrase drops the blocker.

This is the slide to come back to whenever someone proposes "let the model summarise between agents". "Blocked on Apache Spark" becoming "some gaps" is how a warm note reaches someone who cannot do the job.

Capability 1

Runtime

Where it runs.

Serverless container host, per-session microVM isolation, hours-long turns, framework indifferent. You give it a zip or an image; it gives you an ARN.
Runtime

A serverless container host built for agents

Isolation

Each session gets its own microVM — memory and file system cannot leak between conversations.

Long turns

Hours, not the 15 minutes a Lambda gives you. An agent pipeline is not a request/response.

Any framework

It does not care what you built with. It cares that you listen on the right port.

Zip or image

code_configuration from S3, or an ECR image when you need system packages.

The move that matters: the orchestrator stops being a script and becomes a service — so it now needs a bounded turn count, an identity to check and a trace id. None of which a script in terminal 3 ever needed.

Ask: what in your stack currently keeps two users' agent conversations apart? For most teams the honest answer is "a dictionary keyed by user id".
Runtime

The protocol decides the port. Get it wrong and nothing tells you.

🔥 The afternoon-waster

Bind 8080 in an A2A container and the deploy succeeds. The container starts, fails its health check, and what you eventually see is a timeout. Nothing anywhere says "wrong port".

Also note the three A2A agents all listen on 9000. Locally the port was the address — 9001 meant "the screener". Here the ARN is the address and the port is invisible.
Runtime

Three shapes, one platform

HTTP · the front door
app = BedrockAgentCoreApp()

@app.entrypoint
async def invoke(payload, ctx):
    async for ev in stream_pipeline(
        payload["job_id"],
        session_id=ctx.session_id,
    ):
        yield ev        # -> SSE

app.run(port=8080)
A2A · a specialist
from bedrock_agentcore.runtime \
    import serve_a2a

executor = StrandsA2AExecutor(
    agent_factory=build_screener,
    enable_a2a_compliant_streaming=True,
)

serve_a2a(executor, card)
# binds 9000, serves the card,
# handles the health endpoint
MCP · a tool server
mcp.run(
    transport="streamable-http",
    host="0.0.0.0",
    port=8000,
    path="/mcp",
    stateless_http=True,
    show_banner=False,
)

async def + yield is the whole streaming trick: the SDK sees an async generator and returns text/event-stream instead of a JSON body. A plain def still works — it just shows the browser nothing until the last delegation finishes.

stateless_http=True is not optional: Runtime injects an Mcp-Session-Id and load-balances, so a stateful server gets a second request from an instance that never saw the first.

🔥 Minimum length: 33 characters

The obvious value to send is the requisition id — and J2001 is a ValidationException. Do not reach for uuid4(): the session id is what stitches five runtimes into one trace, so a random suffix per hop gives five traces that share nothing. Pad it deterministically.

Sessions are isolated but not free: a new id per request means a cold microVM every time; one id forever means it never expires. Key it to a business object and the lifetime is right for free.
Capability 2

Gateway

What it can reach.

A managed MCP server that fronts things which are not MCP servers: a Lambda, an OpenAPI spec, a Smithy model, an API Gateway stage.
Gateway

A protocol adapter, not a router

flowchart LR
    AG["talent_screening
one flat tool list
from the model's point of view"]
    MCPD["hr_skills_mcp
already speaks MCP
bare: score_match"]
    GWY["hr-gateway

    LAM["hr-data-fn

    AG -->|"direct · 1 hop"| MCPD
    AG -->|"gateway · 2 hops"| GWY

Put a thing behind the Gateway when it cannot speak MCP on its own. Everything else is a hop you pay for on every call, and a tool schema you now maintain twice — in Python and in HCL, with nothing checking them against each other.

Counter-argument worth voicing: routing everything through the gateway gives one console page listing every tool. It loses here because scoring runs once per candidate, per requisition — the hottest path in the system.
Gateway

Tools arrive namespaced — three underscores, not two

hrdata___find_by_skill        hrdata___list_bench
hrdata___get_requisition      hrdata___record_shortlist
def lambda_handler(event, context):
    original = context.client_context.custom["bedrockAgentCoreToolName"]
    tool = original[original.index("___") + 3:]      # split on "__" gets "_find_by_skill"

    if tool == "find_by_skill":
        return find_by_skill(event.get("skill", ""), event.get("min_level", 3))
    return {"error": f"unknown tool {tool!r}"}       # a returned error beats a raised one

event is a flat map of your input schema's properties — {"skill": "pyspark", "min_level": 4} — not an API Gateway envelope. And semantic tool search can only be enabled at gateway creation: there is no update path.

The returned-error rule matters because the return value is the next thing the model reads. Say what to do next — "call find_by_skill and use an id it returned" — not just that it failed.
Capability 3

Identity

Who may ask.

Two directions, two different problems: inbound (who may invoke this) and outbound (what it may reach once running).
Identity

Humans authenticate with Cognito. Machines authenticate with IAM.

flowchart TB
    H(["a human
recruiter in a browser"]) -->|"Cognito ID token · CUSTOM_JWT"| SUP["hiring_supervisor"]
    SUP -->|"SigV4 · execution role"| SPEC["the three A2A specialists"]
    SPEC -->|"SigV4"| MCPR["hr_skills_mcp"]
    SPEC -->|"SigV4 · AWS_IAM"| GWY["hr-gateway"]
    GWY -->|"gateway_iam_role"| LAM["hr-data-fn"]
    LAM -->|"read + write"| S3B[("S3")]
    MCPR -->|"read only"| S3B

You cannot forward the caller's token inward. AgentCore consumes Authorization at its edge and never passes it to your container — so only the front door takes JWT, and everything inside takes SigV4.

Last two edges: two computes read the same bucket for different reasons and exactly one can write. A scoring engine that can edit the employee record is a scoring engine nobody will trust — and IAM is what makes that a guarantee rather than an intention.
Capability 4

Memory

What it carries between Tuesdays.

Two things wear this name and they behave differently — that confusion is worth thirty seconds of the room's attention.
Memory

Events are written now. Records appear later.

Short-term makes a conversation survive a restart. Long-term is semantic search over what was extracted from it.
A memory you wrote thirty seconds ago is not necessarily one you can retrieve yet — extraction is asynchronous. Demos that write and immediately read look broken for this reason.
Memory

actorId is the recruiter. sessionId is the requisition.

config = AgentCoreMemoryConfig(
    memory_id=MEMORY_ID,
    actor_id="recruiter-nk",     # who is working
    session_id="J2001",          # what they are working on
    batch_size=10,
    retrieval_config={
        "/requisitions/J2001/facts": RetrievalConfig(top_k=5, relevance_score=0.4),
    },
)

with AgentCoreMemorySessionManager(config, region_name=REGION) as sessions:
    agent = Agent(system_prompt=SUPERVISOR_PROMPT, session_manager=sessions)

sessionId = uuid4() → a system that forgets J2001 between Tuesday and Thursday.

actorId = "agent" → one shared preference profile for the whole recruiting team.

The with block is load-bearing when batch_size > 1: buffered messages are lost, and the buffer is not flushed on garbage collection. And a SUMMARIZATION strategy will paraphrase "blocked on Apache Spark" into "some gaps" — read memory for context, match() for verdicts.

The headline: session_id is a business key, not plumbing. Pick it badly and everything downstream is wrong in a way that looks like a model problem.
Capability 5

Observability

The only reason you will ever find out what happened.

Metrics are free. Traces take three steps, and each one fails quietly in its own way.

Step 1

Turn on Transaction Search — once per account and region.

Step 2

aws-opentelemetry-distro>=0.18.0 + opentelemetry-instrument.

Step 3

Propagate the session id header on every hop.

Strands already emits OTEL GenAI semantic-convention spans, so tool calls, model calls and token counts appear with no extra code. The screening loop that looked like an unresponsive terminal becomes six identical spans next to their token cost.
Observability

Three failures that look like nothing is wrong

SymptomWhat is actually wrong
The dashboard is empty, the agent answers fineSpans go to X-Ray, not CloudWatch Logs — the role needs xray:PutTraceSegments on top of logs:*. Every export is a 403 the agent survives.
Gateway and Memory logs are emptyOnly Runtime creates its log group. The others need an explicit vended-log delivery — so the busiest component is the silent one.
AccessDeniedException: XRay does not have permission…The console's "enable Transaction Search" checkbox is two operations. The missing half is a log-group resource policy — so there is no role to fix, and IAM shows you nothing.

Transaction Search is also the one setting here whose blast radius is the account, not the stack. It bills, and a terraform destroy turns it back off for everything.

Logs working proves nothing about traces — they are separate deliveries. That single sentence saves a lot of debugging.
Capabilities 6 & 7

Code Interpreter and Browser — and why this system uses neither

Code Interpreter

A sandbox where the agent runs code it wrote. Good for "plot the skill gap across all six requisitions" — open-ended, no fixed function to call.

Never give it match(). A score you cannot reproduce by hand is a score nobody will defend in a hiring review.

Browser

A managed, isolated browser session for systems that only ever had a web UI — half of HR tooling.

Reach for it last. It is the slowest, most brittle integration you own, and the one that breaks because someone else shipped a redesign.

What you needWhere it belongs
Arithmetic your business must defenda plain function in a tool server
An existing Lambda, API or OpenAPI servicea Gateway target
Open-ended analysis over data you just fetchedCode Interpreter
A system with a UI and no APIBrowser — and a note in the risk register
This slide is really about judgement: the platform gives you powerful general tools, and the discipline is knowing which decisions must stay deterministic.

Across five runtimes

Four things must hold for the note to be correct

1

match() computes the blocker — arithmetic in the MCP runtime, never a model call.

2

The screener uses the verdict word exactly: blocked is never softened.

3

The supervisor passes the screening text through verbatim, not summarised.

4

The outreach agent has no HR access at all — it cannot invent a substitute fact.

And the last line of defence is not an agent: the Lambda refuses to persist a blocked shortlist. Everything upstream can paraphrase; the write cannot.

Real war story worth telling: an early compliance reviewer rejected a note for claims "not verified" by a tool it never called. A reviewer that rubber-stamps rejections is as broken as one that rubber-stamps approvals — the fix was to attach the record with a hook instead of asking the model to check.
Field notes

The ones that cost a day each

Wrong port for the protocolDeploy succeeds, health check fails, you see a timeout.
runtimeSessionId < 33 charsValidationException — pad deterministically, never randomly.
A fixed S3 key for the code zipNo diff, no new version: the container keeps running old code while your fix sits in S3.
Declaring a DEFAULT endpointConflictException on every apply — the create call already made one.
Splitting the tool name on __Three underscores. You get _find_by_skill and match nothing.
Leaving an MCPClient contextSilent. The agent keeps the tool names and starts improvising answers.
Semantic search enabled laterCreation-time only — recreating the gateway recreates every target.
compress = true on the API behaviourCloudFront buffers in order to compress, so the stream arrives at the end.
Heavy dependencies30 seconds to become healthy. The failure is HTTP 424, which reads like a client error.
If the deck is running long, this is the slide to linger on and skip the next two — it is the one people photograph.
Adoption

Prove it in this order — steps 1–6 need no agent at all

1–2

S3 + seed data, then the Lambda. Verify find_by_skill("pyspark", 4) returns ['E1002','E1005'].

3–4

Cognito, then the Gateway. tools/list in the MCP Inspector must show four hrdata___* tools.

5–6

The MCP runtime (four unprefixed tools), then both clients in one process — assert eight tools, no duplicates.

7–8

The A2A runtimes — fetch each agent card before sending a message. Then the supervisor.

9–10

Memory: two conversations a day apart. Then Transaction Search and one trace across five runtimes.

11

The UI, locally first. Only once a prompt streams a progress feed is CloudFront worth adding.

Debug the tools with a client that has no model in it. Do not proceed past a step you cannot prove.

Note this is not the order Terraform creates them in — Memory is exercised last but must exist before the runtimes, so it is module 04.

The test that matters most scores the same three candidates twice — from the Python dataset and through the S3 path — and demands byte-identical output. A score that changes when you move the data is a score nobody will defend.

Every failure in AWS has a cheaper version on 127.0.0.1. Five terminals, a local llama, no account needed.
